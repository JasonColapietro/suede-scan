Check reference

Can a crawler fetch and index the page?

These seven checks read the homepage response itself. Two of them can stop indexing outright: a final status outside 2xx and a noindex directive. Google says a page must be indexed and eligible for a snippet before it can appear as a supporting link in AI Overviews or AI Mode (Google Search Central, AI features and your website). Together the seven checks carry 27 of the 90 points.

Page returns a successful response

AccessHigh severity5 of 90 pointsid: status

Repair shown in the report: Return a 2xx status for the public page.

The rule. The scanner requests the URL you submit, follows up to five redirects, and reads the status of the final response. Any status from 200 to 299 passes. Anything else fails, and the observed value shows the code received, such as HTTP 404. A sixth redirect stops the audit with an error, and so does a response that declares a non-HTML content type.

Why it matters. Google does not use content from URLs that return 4xx codes, and it removes already indexed URLs that start returning them. Even a 2xx only makes the content eligible: the indexing systems may index it, but that is not guaranteed (Google, how HTTP status codes affect its crawlers).

How to fix it. Serve the canonical homepage with 200. Point old addresses at it with one permanent redirect rather than a chain, and make error templates return 404 or 410 instead of 200 so they are not mistaken for content.

Page is served over HTTPS

AccessHigh severity5 of 90 pointsid: https

Repair shown in the report: Serve the page over HTTPS and redirect the HTTP version.

The rule. Passes when the final URL, after redirects, uses https. A bare domain such as example.com is requested over HTTPS first. If you submit an http:// address, the check passes only when the server redirects it to an https:// URL.

Why it matters. Google's page experience guidance asks whether your pages are served in a secure fashion and points site owners to the Search Console HTTPS report (Google, understanding page experience).

How to fix it. Install a certificate, redirect every http:// URL to its https:// twin with a permanent redirect, and use https:// addresses in canonical tags, sitemap entries and internal links.

Page can be indexed

AccessHigh severity5 of 90 pointsid: noindex

Repair shown in the report: Remove the noindex directive if the page should be discovered.

The rule. The scanner reads the first meta tag named robots in the HTML. The check fails when its content contains noindex in any letter case. The observed value shows the directive found, or "No robots meta block" when the tag is absent. This check reads the generic robots tag in the HTML; review the X-Robots-Tag response header and crawler-specific tags such as googlebot in the same pass.

Why it matters. Google's robots meta specification defines noindex as "Do not show this page, media, or resource in search results" (Google, robots meta tag specifications). A noindex homepage cannot be indexed, so it cannot be a supporting link in Google's AI features either.

How to fix it. Remove noindex from every page you want found. If a staging or preview build sets it, make sure the production build drops it, then rerun the audit against the live domain.

Canonical link is declared

TechnicalMedium severity3 of 90 pointsid: canonical

Repair shown in the report: Add a canonical URL for the preferred page version.

The rule. Passes when any link element lists canonical among its rel values. The check confirms the tag exists. The evidence summary at the top of the report shows the href it points to, so you can confirm it names the version you want indexed.

Why it matters. Google treats a rel="canonical" link as a strong signal that the named URL should become canonical, alongside redirects, while sitemap inclusion is a weak signal (Google, how to specify a canonical).

How to fix it. Add <link rel="canonical" href="https://www.example.com/"> to the head, using the absolute URL of the preferred version. Keep it consistent with your redirects and sitemap entries so the signals agree.

Mobile viewport is declared

TechnicalHigh severity5 of 90 pointsid: viewport

Repair shown in the report: Add a responsive viewport meta tag.

The rule. Passes when the page has a meta tag named viewport with a non-empty content value.

Why it matters. Google uses the mobile version of a site's content, crawled with the smartphone agent, for indexing and ranking (Google, mobile-first indexing best practices). Its page experience guidance also asks whether your content displays well on mobile devices. The audit weights this check high.

How to fix it. Add <meta name="viewport" content="width=device-width, initial-scale=1"> to the head of every template, then confirm the layout reads cleanly at phone width.

Document language is declared

AccessLow severity1 of 90 pointsid: language

Repair shown in the report: Set the html lang attribute.

The rule. Passes when the opening html tag carries a quoted lang attribute with any value. The observed value shows the code found, such as en or en-US. Quote the value: an unquoted lang=en is not read.

Why it matters. Google says it determines language from the visible content of a page and does not use lang attributes (Google, managing multilingual sites). The attribute serves people and their tools: WCAG 2.2 Success Criterion 3.1.1 requires that the default human language of each page can be programmatically determined, so screen readers pronounce the text correctly (W3C, Understanding SC 3.1.1). The audit weights it low.

How to fix it. Set <html lang="en">, or the code for your page's language, in the base template.

HTML response stays under 300 KB

PerformanceMedium severity3 of 90 pointsid: html-weight

Repair shown in the report: Reduce server-rendered HTML and inline payloads below 300 KB.

The rule. The scanner measures the HTML document it received in UTF-8 bytes, divides by 1,024 and rounds. 300 KB or less passes. The observed value also counts script tags and inline style attributes to show where the weight sits; those counts are not scored. The scanner reads at most 1.5 MB of HTML, and a larger page stops the audit with an error.

Why it matters. When crawling for Google Search, Googlebot fetches the first 2 MB of an HTML file, measured uncompressed, and sends only the part it downloaded before the cutoff for indexing consideration (Google, what is Googlebot). The 300 KB threshold is the audit's own rule and sits well inside that cutoff.

How to fix it. Move inline scripts and data blobs into cached external files, remove unused markup from templates, and avoid embedding images as data URIs in the HTML.
