Check reference

Give crawlers a page they can read and follow.

These checks read the served HTML of the homepage, before any JavaScript runs. Text, headings and links that only appear after scripts execute are not counted. Google renders JavaScript, but its documentation calls server-side or pre-rendering a great idea because not all bots can run JavaScript (Google, JavaScript SEO basics). The sixth content check, section length, has its own page: retrieval chunk size.

Page has exactly one H1

ContentMedium severity3 of 90 pointsid: h1

Repair shown in the report: Use one H1 that states the page subject.

The rule. Counts h1 opening tags in the served HTML. Exactly one passes. None, or two or more, fails.

Why it matters. Google's SEO Starter Guide recommends breaking content into sections with headings so readers can navigate, and notes that semantic heading order helps screen readers (Google, SEO Starter Guide). A single H1 gives the page one stated subject. The report's evidence summary shows that H1 next to the title so you can check they agree.

How to fix it. Keep one H1 that names what the page is about. Demote logo text and repeated banners to other elements.

Page uses explanatory H2 sections

ContentMedium severity3 of 90 pointsid: h2

Repair shown in the report: Break the page into at least two descriptive H2 sections.

The rule. Counts h2 opening tags in the served HTML. Two or more passes.

Why it matters. Headings mark where one topic ends and the next begins. Google Cloud's Agent Search layout parser, for example, identifies text blocks, tables, lists, titles and headings and uses them to define a document's hierarchy, and its layout-aware chunking keeps each chunk inside one layout entity (Google Cloud, parse and chunk documents).

How to fix it. Give each major section an H2 that names its question or topic, such as pricing, how it works or who it is for.

Page has substantive readable content

ContentMedium severity3 of 90 pointsid: content-depth

Repair shown in the report: Add direct, answer-ready copy that explains the subject in at least 300 useful words.

The rule. Removes scripts, styles and comments, strips the remaining tags, and counts whitespace-separated words, navigation and footer included. 300 or more passes.

Why it matters. Google says length alone does not matter for ranking and there is no magical word count (Google, SEO Starter Guide). The 300-word floor is the audit's test that the homepage explains itself in server-rendered text. Google lists making important content available in textual form among the fundamentals for AI Overviews and AI Mode (Google, AI features and your website).

How to fix it. State what you offer, who it serves and how it works in plain HTML text. Replace text baked into images with real text.

Page points to supporting internal evidence

ContentMedium severity3 of 90 pointsid: internal-links

Repair shown in the report: Link to at least three relevant internal pages with descriptive anchor text.

The rule. Counts anchor elements with a quoted href whose resolved hostname matches the audited host. Links that start with #, mailto:, tel: or javascript: are skipped, and links to another subdomain count as external. Three or more passes. The observed value reads, for example, "12 internal of 18 links".

Why it matters. Google uses links to judge relevance and to find new pages, and can generally crawl a link only when it is an a element with an href. It asks for anchor text that is descriptive, reasonably concise and relevant (Google, link best practices). Its AI features guidance lists making content findable through internal links.

How to fix it. Link from the homepage to the pages that support your claims, such as pricing, documentation and case studies, using real a href elements rather than click handlers.

Images declare alt attributes

ContentLow severity1 of 90 pointsid: image-alt

Repair shown in the report: Add alt attributes to images missing them. Describe informative images; keep alt="" for decorative images. Review purpose in context.

The rule. Finds every img tag outside scripts, styles and comments and reads its alt attribute. The check fails when any image has no alt attribute at all. An empty alt="" passes. The observed value splits images into non-empty, empty and missing.

Why it matters. Google uses alt text with computer vision and page content to understand what an image shows (Google, image SEO best practices). The W3C says decorative images take a null alt, and that leaving the attribute out makes some screen readers announce the file name instead (W3C, decorative images).

How to fix it. Describe informative images in a short phrase and set alt="" on decorative ones.

More check references

  • Page access and indexing: Status code, HTTPS, noindex, canonical, viewport, language and HTML weight.
  • Crawler access: How robots.txt is read for OAI-SearchBot, Claude-SearchBot, PerplexityBot and Googlebot.
  • Discovery files: Whether robots.txt, sitemap.xml and llms.txt answer at the site root.
  • Structured data and entity: Valid JSON-LD, a primary entity type, and sameAs identity links.
  • Titles, descriptions and share metadata: Title and description length, Open Graph, X card and favicon.
  • Retrieval chunk size: Whether every heading section fits in one 375-word retrieval chunk.
