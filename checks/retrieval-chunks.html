Check reference

Does each section fit in one retrieval chunk?

Retrieval systems such as Google Cloud's Agent Search split documents into chunks that are then used for retrieval and answer generation. This check estimates whether each section of your homepage fits in one chunk together with the heading that names it. It is a medium-severity Content check worth 3 of the 90 points.

Page sections fit one retrieval chunk

ContentMedium severity3 of 90 pointsid: chunking

The check passes when the homepage serves at least 100 words of text, has at least one heading, and holds no heading section over 375 words. The sections below explain where that number comes from, how the page is split, and what each result means.

Where the 375-word limit comes from

Google Cloud's Agent Search documentation sets a token limit for each chunk in layout-based chunking: 500 by default, with supported values from 100 to 500. An optional setting appends the title and headings to chunks from the middle of a document, which the documentation says can help prevent context loss in retrieval and ranking (Google Cloud, parse and chunk documents).

The audit converts the 500-token ceiling at about 0.75 words per token, which gives 375 words. Token counts vary with vocabulary, so treat 375 as a working ceiling rather than an exact count.

How the scanner splits the page

  1. Remove comments and script, style, noscript, svg and template elements. Drop nav and footer elements entirely, because site chrome is not the prose a chunk competes for. Header elements stay, because article pages often place the H1 inside one.
  2. Find every heading from H1 to H6. Each heading starts a section that runs to the next heading of any level.
  3. Count the words in each section. Text before the first heading counts as its own section.
  4. Compare every section with 375 words.

The four results

Page stateResultObserved value
Fewer than 100 words of text in totalRepair"N words of server-rendered text, too little to evaluate"
100 words or more, no headingsRepair"N words, no headings anywhere on the page"
Any section over 375 wordsRepairHow many sections are over the limit, and the largest one with its heading
Every section 375 words or fewerPass"All N heading sections fit", with the largest one named

The first result is aimed at pages whose copy arrives through JavaScript, which leaves little text in the served HTML. The report's repair for it reads: "Server-render the page copy. A retrieval crawler chunks the HTML it is served, so text that arrives client-side is not chunked at all."

How to fix an oversized section

Split the section at its natural subtopics and give each part its own H2 or H3 that names it. Keep each claim close to the heading that identifies it, so the claim and its context land in the same chunk. Question-and-answer blocks and short definitions fit well, because each one can carry its own heading. Then rerun the audit: the observed value names the largest remaining section and its word count.
